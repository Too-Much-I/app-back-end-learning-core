## 1. 5줄 결론

1. 각 파트의 첫 번째 세트 전체를 무료 제공하고 두 번째 세트부터 유효한 학습 이용 권한을 요구한다.
2. 세트는 목록 카드(unit), 문항은 하위 lesson이다. Part3 첫 세트 Q5/6/7과 Part4 첫 세트 Q8/9/10도 전부 무료다.
3. 앱은 기존 목록의 순서와 lessons.completed로 첫 미완료 세트를 계산한다. 별도 이어 풀기 API/응답 필드/진도 저장은 추가하지 않는다.
4. 세트에 미완료 문항이 있으면 같은 세트, 모든 문항이 완료되면 다음 세트를 안내한다. 접근 잠금과 진도는 별개로 계산한다.
5. Billing 학습 권한 조회 계약과 공개 API 확장을 먼저 확정하고, LC·프론트 구현/테스트 뒤 별도 배포 승인으로 적용한다.

## 2. 사용자가 알아둘 동작

### 2.1 확정 요구와 용어

| 구분 | 내용 |
| --- | --- |
| 무료 범위 | 각 파트 첫 세트 전체. 모든 세트의 첫 문항 무료가 아님 |
| 유료 범위 | 두 번째 이후 세트는 이용권 필요 |
| 세트 | `learning_units`의 카드 하나 |
| 문항 | `learning_lessons`의 질문 하나 |
| Part1/2/5 | 카드당 1문항 |
| Part3 | 카드당 Q5/6/7의 3문항 |
| Part4 | 카드당 Q8/9/10의 3문항 |
| 이어 풀기 요구 | 세트 미완료면 같은 세트, 전체 완료면 다음 세트 안내 |

세트 순번 1/2/3과 실제 문항 번호 Q5/Q6/Q7은 다른 축이다. Part3의 다음 세트에서도 질문 번호는 Q5부터 시작하며 Q8로 증가시키지 않는다. 재응시 횟수나 words 배열 인덱스를 문항 번호로 사용하지 않는다.

### 2.2 확정 동작 — 세트 단위 이어 풀기

- 이어 풀기의 반환·이동 대상은 세트다. 세트 안에서 어느 문항을 선택할지는 기존 화면 동작을 유지하며 자동으로 첫 미완료 문항에 이동시키는 요구를 추가하지 않는다.
- Part3 첫 세트에서 Q5만 완료했다면 첫 세트를 다시 안내한다. Q5/6/7 모두 완료했다면 두 번째 세트를 안내한다.
- Q6만 먼저 완료한 경우에도 첫 세트가 미완료이므로 같은 첫 세트를 안내한다. 남은 문항 번호를 이어 풀기 대상으로 반환하지 않는다.
- 파트·등급·콘텐츠 버전별 완료 기록을 재사용하고 홈에서는 카탈로그 순서상 첫 미완료 세트를 안내한다. 1세트 미완료 상태에서 5세트를 학습해도 홈에서는 1세트를 안내한다. 마지막 방문 세트는 저장하지 않는다.
- 채점 대기 문항은 아직 완료가 아니다. 기존 제출 ID를 알고 있으면 해당 결과 조회를 이어가며 자동 새 제출·자동 재과금을 만들지 않는다.
- Part2~5는 기존 worker의 완료 기록 저장과 명시 completion API를 재사용한다. Part1은 기존 비교 후 completion 저장 방식을 유지한다.
- 모든 세트 완료 시 `모두 완료` 상태를 안내한다. 임의 순환·완료 기록 초기화 없이 사용자가 카드를 선택해 복습한다. 복습도 기존 무료/유료 접근 조건을 따른다.
- 유료 잠금 상태의 다음 세트도 진도상 다음 대상으로 안내할 수 있지만, 진입에는 이용권 안내를 표시한다. 무료 세트로 자동 우회하지 않는다.

세트 완료 판단과 홈 이어 풀기는 기존 목록 응답으로 앱에서 계산한다. 서버 완료 기록이 원본이며, 앱이 마지막으로 조회한 목록보다 다른 기기의 진도가 앞서면 재조회 전까지 표시가 늦을 수 있다. 마지막 방문·문항·학습 단계 복원은 추가하지 않는다. 같은 세트 안내는 완료 기록 초기화나 이미 완료한 문항의 강제 재학습을 뜻하지 않는다.

## 3. 확정 사항과 남은 기술 확인

2026-10-23 사용자 확정: 파트별 학습은 Billing의 현재 학습 이용 가능 여부만 조회한다. 학습 시작으로 이용권 활성화·기간 개시/연장·차감·소비를 수행하지 않는다. 세트는 콘텐츠/진도 단위이며 별도 세트 예약·이용권 연결·시작 허가 저장 시스템은 추가하지 않는다. Billing의 기존 상품 기간 정책을 그대로 따른다. 조회 API의 exact 계약 및 시간 검증 세부사항은 공동 확인 대상으로 남긴다.

최신 보완본: 최초 출시로 기존 사용자 예외·이관은 불필요하다. 유료 콘텐츠 제공만 무캐시 조회하고 create/submit/채점에는 이용권 조회를 하지 않는다. 본인 인증으로 직접 채점 API를 호출할 수 있는 잔여 위험은 사용자 승인으로 수용했다. 기존 인증·소유권·삭제·탈퇴·제출 상태/기간 보호는 유지하고, 별도 세트 시작/승인 기록·분산 예약·즉시 회수 시스템은 만들지 않는다.

| 항목 | 권장안 / 공동 확인 |
| --- | --- |
| 이어 풀기 의미 — 확정 | 홈은 순서상 첫 미완료 세트. 일부 미완료면 같은 세트, 전체 완료면 다음 미완료 세트 안내. 모두 완료면 완료 표시 및 수동 복습. 문항 위치 복원 제외 |
| 무료 세트 식별 — 확정 | 파트별 고정 unitId 설정을 한 곳에 보관. 별도 관리 화면/DB 컬렉션 없음. 콘텐츠 버전과의 일치 검증 유지 |

| 만료·환불 경계 | 유료 콘텐츠 제공 결정 시만 validUntil 확인. create/submit에는 이용권 검사 없음. 직후 경합 및 직접 채점 호출 위험 수용, 기존 처리 유지 |

| 캐시·서명 URL | 요청 간 캐시 없음. 구매 후 다음 학습 요청도 새 조회. 음성 URL 기존 유효기간은 Billing 조회5초와 별개이며 잔여 접근 허용 |
| 공개 wire | 기존 URL/DTO를 깨지 않는 추가 조회 계약 또는 승인된 필드 추가 중 선택. 미승인 필드/오류 이름을 확정으로 구현하지 않음 |

기간제·권리 선택은 Billing 책임이다. 모의고사 reserve/confirm을 호출하거나 체험 무료권·복원권을 소모해 학습을 여는 방식은 사용하지 않는다. 결제 구매 요구 외의 추가 소비 정책은 사용자 승인 없이 만들지 않는다.

Billing 제안은 별도 `POST /internal/v1/entitlements/part-learning-eligibility`다. 기존 재답변 API의 무료권 허용 및 요청별 조회 규칙은 변경하지 않는다. LC는 인증된 userId만 body에 전달하고 기존 workload 키/issuer와 전용 audience `tosunsaeng-billing:part-learning-eligibility:{env}`를 사용한다. 멱등키는 없다. 앱 구매 정보로 서버 판정을 대체하지 않는다.

응답은 wrapper 없는 userId/decision/reason/checkedAt/validUntil이다. 제안 조합은 ALLOWED/ACTIVE_PAID_ENTITLEMENT, DENIED/PAID_ENTITLEMENT_REQUIRED, DENIED/ACCOUNT_WITHDRAWN, PENDING/ENTITLEMENT_STATE_UNCONFIRMED이며 비허용 validUntil은 null이다. ALLOWED의 validUntil은 min(checkedAt+5초, 해당 유료권 endsAt), UTC 문자열 정밀도를 유지한다. reason exact 값과 기존 strict/본문 크기/시각 검증 규격의 참조 revision은 공동 동결해야 한다.

Billing 검토 회신 반영: 유료권은 기존 단일 ACTIVE slot 판정을 유지하고 위 endsAt은 activeEndsAt을 뜻한다. 중첩 정합성 실패는503이며 최대 종료나 미래 scheduled 종료를 선택하지 않는다. 요청/응답은 각각16,384bytes, 내부400도500으로 매핑한다. 미래 checkedAt 허용오차 없이 `checkedAt <= receivedAt < validUntil`, `receivedAt <= guardNow < validUntil` 및 호출 직전부터 monotonic elapsed가 수신/사용 모두0이상5초미만임을 검증한다. 단순 지연/만료503, 미래/역행/모순500이다. 원격 HTTP는 LC 쓰기 Transaction 밖, Billing 내부는 기존 read-only snapshot이며 checkedAt을 재시도로 연장하지 않는다. 참조 draft-5 hash 대조 결과와 세부 규격은 권장안 review-2에 기록했다. 아직 신규 wire 최종 동결·실행 검증을 뜻하지 않는다.

공개 오류는 기존402 ENTITLEMENT_INSUFFICIENT(학습 안내: 유료 이용권이 필요합니다),401 ACCOUNT_WITHDRAWN,503 BILLING_TEMPORARILY_UNAVAILABLE, 내부 인증/주소/계약 오류500 COMMON500+운영 경보다. 학습 전용 Advice에 명시 매핑하고 내부401을 사용자401로 전달하지 않는다. 연결2초/요청5초/요청 내 자동 재시도 없음. 정상 응답이라도 사용 시 만료됐다면 허용하지 않으며 만료503 및 malformed 계약500 구분 등 exact 시간 규칙을 공동 확인한다. 유효 paid가 있으면 다른 구매의 pending sync만으로 거절하지 않으며 상태 불명은 부족으로 단정하지 않는다.

## 4. 주요 위험과 미확인 사항

### 승인된 일일 제출 한도

- 신규 학습 submission 생성은 사용자별 하루300회로 제한한다. 기존 일일 카운터를 재사용하며 무제한안은 채택하지 않는다.
- 실패한 submission의 허용된 재시도는 일일 한도에서 제외한다. 기존 retryable 조건·건별 attempt 상한·재시도 가능 기간은 유지하며 별도 일일 재시도 카운터는 만들지 않는다.
- 같은 submission ID의 정상 replay는 기존처럼 추가 차감하지 않는다. 새 녹음으로 신규 submission을 만들면 신규 생성으로 계산한다.
- 생성 후 업로드/제출을 하지 않은 건도 횟수에 포함한다. UTC 날짜 기준(한국 시간 오전9시 초기화)을 유지한다. Part1은 기존처럼 해당 submission 생성 대상이 아니다.
- 구현 시 기본 설정60을300으로 변경하고 retry의 일일 quota 증가를 제거한다. 운영 환경변수 override도 전달 단계에서 별도 확인한다. 기존 당일 카운터의 과거 재시도분을 소급 재계산하거나 DB를 수정하지 않는다.
- 이 절은 정책/구현 계획 승인 기록이며 실제 코드·운영 설정 변경 완료를 의미하지 않는다.

### 기존 접근·콘텐츠 확인 사항

- 현재 LC answerlearning 코드에는 이 요구를 충족하는 Billing 학습 접근 검증이 확인되지 않았다. 시험 예약 계약을 학습 권한 조회 계약으로 간주하지 않는다.
- 프론트 카드 잠금 외에 LC 본문/미디어 제공에서 유료권을 검사한다. 제출 경로의 유료권 검사는 하지 않으며 직접 채점 요청 가능성은 승인된 위험이다. 제출의 기존 소유권/삭제/상태 검증은 유지한다.
- 목록 응답은 제목·썸네일·진도 같은 허용된 요약만 제공한다. 잠금 상세를 모두 내려주고 UI에서만 감추지 않는다.
- 이미 발급·다운로드된 콘텐츠는 나중의 권한 검사로 회수할 수 없다. 기존 URL 만료/앱 캐시의 한계를 명시한다.
- 기존 완료 기록은 userId/lessonId/level/contentVersion 단위다. 다른 등급/새 버전으로 자동 완료 이전하지 않는다. 새 버전 진도 이전은 별도 결정이다.
- 파트 번호·문항 번호·title·sortOrder만으로 무료 권한을 결정하면 재정렬/콘텐츠 교체에서 범위가 바뀐다. 명시 매핑과 검증이 필요하다.
- 삭제/탈퇴/owner deny는 무료·유료 구분 없이 우선한다. 권한 오류를 일반 장애와 합치거나 장애 시 유료 콘텐츠를 무료 허용하지 않는다.
- Notion 화면·실제 프론트 코드·운영 Billing 학습 권한 API는 이번에 확인하지 않았다. 화면 문구·호출 조합과 공동 wire 확정은 남아 있다.

## 5. 구현 설계

### 5.1 접근 판단

1. 기존 인증 및 owner/삭제/탈퇴 guard를 적용한다.
2. 현재 publication ready 카탈로그에서 unit/lesson/media 관계를 확인한다.
3. 해당 파트의 명시 무료 unit이면 Billing 장애와 무관하게 무료 범위 내 허용한다.
4. 유료 본문·음성 제공만 공통 client로 요청마다 Billing에 조회한다. create/submit에는 조회하지 않는다. 요청 간 허용 결과를 공유하지 않으며 사용자 인증·현재 소유권·삭제·탈퇴 검사도 유지한다.
5. 권리 없음·만료/환불, 회원 증거 대기, 인증/계약 오류, 통신 장애를 구분한다. exact HTTP/code는 공동 계약에서 확정한다.

Billing 응답을 사용자 body의 paid=true, 구매 ID, 완료 기록 등으로 대체하지 않는다. 기존 시험 권한 모델·역방향 환불 이벤트를 학습까지 자동 확장하지 않는다. 최소한의 필요한 판정만 반환받으며 금융 원장을 LC에 복제하지 않는다.

### 5.2 보호할 경로

유료 콘텐츠 제공에만 요청별 조회를 연결한다. 단순 목록·진도·기존 결과/polling과 create/submit/retry에는 연결하지 않는다. 세트 시작 상태·허가 기록·새 예약 saga·환불 consumer·승인 receipt·복구 worker는 추가하지 않는다. Job 복구/중복 요청의 기존 상태 검증은 유지하되 이를 Billing 재조회 예외를 위한 새 승인 구조로 확장하지 않는다.

| 기존 경로 | 계획 |
| --- | --- |
| GET /learning/units | 기존 정렬된 요약/문항 완료 목록 유지. 이어 풀기 계산용 확장 없음. 접근 표시 계약만 필요 시 별도 합의 |
| GET /learning/units/{id} | 본문/모범 답안/음성 URL 반환 전에 unit 접근 검사 |
| GET /learning/media/{id}/url | 소속 unit 관계 확인. 유료 음성 발급 전 무캐시 조회, 무료 세트/공용 썸네일 구분 |
| GET /learning/capabilities | 준비 상태만 반환하면 미조회. 유료 콘텐츠가 포함되면 해당 제공에 검사 |
| POST /learning/submissions | 제출 준비만 하므로 미조회. 유료 본문/음성을 추가한다면 해당 제공에 검사. 기존 same-id replay/owner 유지 |
| upload-url / submit | Billing 미호출. 기존 소유권·문항·제출 상태·기간·중복 처리 및 파일/queue 흐름 유지 |
| GET /submissions/{id} | 기존 소유자의 접수 결과 조회와 신규 콘텐츠 접근을 분리 |
| retry / completion | 기존 접수 건의 재처리/완료 유지. 새 학습 요청과 기존 접수 처리를 구분하되 Part1 포함 별도 세트 상태 시스템은 없음 |

표의 경로는 공통 `/api/v1` 접두사를 생략한 기존 경로다. media 공유·역참조 검사가 불가능한 자료는 임의 허용하지 않고 카탈로그 검사에서 검출한다. 외부 HTTP 권리 조회는 Mongo Transaction 밖에서 수행하고 로컬 write 시 기존 owner fence를 유지한다. 조회 후 환불 경합의 허용 범위는 Billing 계약에 명시한다.

### 5.3 저장·진도

- 기존 learning_completions를 완료의 유일 근거로 재사용한다. 세트 완료 boolean·문항 목록·복제 완료 테이블을 추가하지 않는다.
- 앱은 기존 목록의 lessons.completed 전체가 true인지 확인하고 응답 순서대로 첫 미완료 unit을 선택한다. 서버는 기존 정렬(sortOrder, ID)과 완료 기록 조회를 유지한다.
- 첫 무료 unit ID는 파트별 고정 설정 한 곳에 둔다. 변경 시 설정을 수정하며 새 DB 컬렉션/관리 UI는 만들지 않는다.
- 파트별 매핑의 존재/소속/ready 여부를 시작·콘텐츠 배포 검증에서 확인하고, 매핑 부재 시 다음 세트를 임의 무료로 승격하지 않는다.
- 완료 row merge/삭제는 기존 LearningOwnership 및 학습 삭제 대상 연결을 유지한다. 이어 풀기용 새 진행 컬렉션은 추가하지 않는다.
- 신규 DB index가 필요하다면 조회계획 확인 후 별도 dry-run/승인으로 처리한다. 계획 작성 자체로 실DB 설치하지 않는다.

### 5.4 프론트·공개 응답

공개 API 확정 전 다음 의미만 합의한다. 필드명과 route는 후보이며 기존 DTO를 바로 변경하지 않는다.

- 접근 정보: unit별 무료/콘텐츠 이용 가능/이용권 필요/확인 불가를 구분한다. 제출의 서버 검증은 기존 소유권·상태·한도이며 유료권 판정은 포함하지 않는다.
- 이어 풀기는 기존 목록의 units 및 lessons.completed로 앱에서 계산한다. 별도 대상 unitId·모두 완료 필드나 신규 이어 풀기 route는 만들지 않는다. 목록 실패/불완전 자료를 모두 완료로 추정하지 않는다.
- 모든 학습 완료 row를 클라이언트가 추측해 만들거나 화면 방문만으로 완료 처리하지 않는다.
- 이어 풀기는 순서상 첫 미완료 세트 화면으로 연결한다. 세트 안의 기존 문항 자유 선택은 임의 제거하지 않는다.
- 구매 완료 후 권한 재조회, 복귀 시 최신 진도 조회. 장애/권리 불명은 무료 fallback 금지. 접수 중인 제출은 기존 ID로 조회한다.

Billing은 권리 사실과 읽기 전용 조회 계약을 담당한다. LC는 요청별 조회·시간/오류 검증·기존 완료 목록을 담당한다. 프론트는 기존 목록 기반 이어 풀기 계산과 구매 유도·선택/복귀 UI를 담당한다. 이번 LC 계획이 타 저장소 변경 권한을 뜻하지 않는다.

## 8. 단순화 경계 및 다음 작업

새 결제 원장·학습 예약 saga·progress 이벤트/outbox·세트 완료 테이블·word별 진도·운영 관리 UI는 만들지 않는다. 기존 완료 기록 재사용으로 시작하고, 정말 마지막 방문 복원이 필요할 때만 저장 범위를 넓힌다.

주요 사용자 정책 선택은 완료됐다. 다음은 Billing 학습 권한 조회·공개 응답·무료 unit 매핑 등 P0 기술 계약 보완이며, 후속 구현 요청에 따라 P1로 진행한다. 이번 정책 승인을 코드/DB/배포 승인으로 확대하지 않는다. 기존 A/시험 fixture bytes를 수정하거나 시험 유료 예외를 학습에 그대로 적용하지 않는다.
